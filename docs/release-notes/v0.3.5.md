# v0.3.5 — Cox 改用 npm 安装与更新

## 更新

- **统一 npm 分发**：本地 Cox 从 `@doublepi123/cox` 安装，不再依赖 Android 专用服务端压缩包。首次安装解析 npm 的最新稳定标签，再安装确定版本；查询失败时使用清单中的 `0.1.15` 作为备用版本。
- **兼容已有环境**：已有 Cox 压缩包即使版本相同，也可以迁移到 npm；旧 T3 Code 环境继续支持启动和迁移，不跨产品比较版本，不降级已有 Cox。
- **原生依赖验证**：在 Alpine/PRoot 内重建 node-pty，验证原生模块、PTY 与 Cursor SDK 离线预热。安装及更新在 staging 中进行，验证失败保留活动环境、项目和用户数据。
- **同步密码变量**：Cox 同时接收 `COX_AUTH_PASSWORD` 和同值的旧变量，兼容新旧版本。旧 T3 Code 只接收旧变量，OpenChamber、安装及 CLI 登录环境不接收服务端密码。

## 升级方式

安装 APK 后，在本地环境中检查并执行更新，然后重启 Cox。无需删除现有环境、项目或会话。仅安装新版 APK 不会自动迁移正在运行的服务端。

## 验证范围

- 606 项 JVM 测试、61 项 Python 测试与 Debug APK 构建通过。
- Raspberry Pi 400 ARM64 实机上的 Alpine 容器通过 Cox 0.1.14 原生模块、PTY、SDK 离线预热、服务启动、密码认证及 HTML 检查；这不是 ARM64 Android 验证。
- Android 15 x86_64 模拟器通过 12 项 PRoot 基础探针，以及真实 npm 安装、合成旧包布局启动、同版本迁移、失败回滚、用户数据保留与重启认证测试。合成布局测试不等于安装历史发布包。
- Cox 0.1.14 和 0.1.15 在 x64 Alpine 中均通过新旧密码变量兼容性验证。未调用付费模型，未修改正式应用数据。

## English

- Install and update Cox through the standard `@doublepi123/cox` npm package instead of Android-specific server archives. Resolve the latest stable tag for fresh installs, with 0.1.15 as the manifest fallback.
- Offer same-version migration from existing Cox bundles while retaining legacy T3 Code startup and migration. Rebuild native PTY dependencies and verify the staged environment before activation; preserve user data and the active runtime on failure.
- Set the canonical Cox password variable alongside its matching legacy alias, without sharing server passwords with OpenChamber, installer or CLI-login processes.

After installing the APK, update the local runtime and restart Cox. Existing projects and sessions do not need to be removed. Coverage includes 606 JVM tests, 61 Python tests, native ARM64 Alpine smoke tests, and Android 15 x86_64 emulator PRoot/install/migration/rollback/authentication checks. ARM64 Linux results are not ARM64 Android coverage, and the legacy-layout fixture is not a historical release artifact. No paid inference was performed.
