# v0.3.3 — 修复 Android 上 Cursor SDK 初始化失败与登录黑屏

## 修复

- **Cursor SDK 初始化失败**：SDK 自带的 tree-sitter 原生库依赖 glibc。在 Alpine 环境缺少兼容加载器时，首次加载失败，后续可能只显示 `Cannot access 'uR' before initialization`。新安装加入 `gcompat`；已有环境在更新、调整代理或服务时，也会先在 staging 内补齐依赖并验证。失败不会替换正在使用的环境。
- **安装后验证 SDK**：新版 Cox 包执行离线预热检查，旧 SDK 包直接检查两个原生库。检查使用临时配置和工作目录，不发送模型请求。
- **登录失败不再误判为成功**：要求登录接口明确返回 `authenticated: true`，而不只检查 HTTP 200；主页面 HTTP 错误显示可操作的错误面板，避免留下黑屏。
- **内嵌 Cox 升级到 0.1.9**：包含登录入口恢复、手机底部模型选择面板和 Cursor SDK 发布检查。仅当当前设备架构的包及校验和已经发布时，才提示更新。

## 升级方式

安装此 APK 后，在本地环境中检查并执行更新，然后重启 Cox。仅安装 APK 或替换 Cox 压缩包，不会立即修复已经运行的旧环境。无需删除现有环境、项目或会话。

## 验证范围

- 602 项 JVM 测试与 release APK 构建通过。
- 实体 ARM64 Android 设备上，用公开发布的 Cox 包复现首次原生库加载错误及后续初始化错误；补齐兼容库后，Cox 0.1.9 的离线 SDK 检查、两次实际会话创建/关闭、完整服务内连续预热均通过。
- 真机测试在隔离诊断应用中进行，没有修改正式应用数据，也没有调用付费模型。未将该结果扩大为所有设备、全部 SDK 功能或厂商后台策略验证。

## English

- Install and repair Alpine `gcompat` in staging for Cursor SDK's glibc tree-sitter bindings. Missing compatibility libraries cause the first native load to fail and subsequent calls to report a secondary SDK initialization error. Failed verification does not activate the staged environment.
- Run the new bundle's offline SDK prewarm check, or load both native bindings for older SDK bundles. No model requests are sent.
- Require an explicit authenticated login response and show main-frame HTTP errors instead of leaving a blank page.
- Embed Cox 0.1.9, retaining the restored sign-in gate and phone model-picker sheet. Offer a runtime update only after this device's bundle and checksums are available.

After installing this APK, update the local runtime environment and restart Cox. Installing the APK or replacing the Cox archive alone does not repair an already running environment. Existing projects and sessions do not need to be removed.

Validation: 602 JVM tests and the release build passed. In an isolated application on a physical ARM64 Android device, the published Cox 0.1.9 bundle passed offline SDK prewarming, two real runner open/close cycles, and repeated prewarming inside the full server after compatibility libraries were supplied. No production application data was modified and no paid inference was performed.
